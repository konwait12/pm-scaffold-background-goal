# 背景四要素

写背景时至少回答四件事：谁受到影响、在什么业务情境下、发生了什么问题、问题造成了什么可观察影响。

量化数据有就写基线、频率、规模或时间；没有就标为待确认，不补造数字。背景描述要与目标相互对应，但不要把解决方案写成目标。所有数据和情境都必须来自本次任务材料或 PM 的明确回复。

## 基线数据引导（材料未给量化数据时必做）

当原材料没有给出规模 / 频率 / 基线数据时，不要直接标 UNKNOWN 结束，先向 PM 提供取数路径清单，引导补齐：

| 取数路径 | 适用数据 | 引导话术示例 |
|---|---|---|
| 产品埋点 / 行为日志 | 用户行为频率、功能使用量、转化漏斗 | 「这个动作在埋点里能拉到吗？周期取最近 30 天还是 90 天？」 |
| 抽样统计 | 无法全量取数时的规模估计 | 「能否随机抽一周的样本估算日均量级？」 |
| 第三方 BI / 报表系统 | 已有经营指标、留存、负载 | 「团队现在看数据用哪个报表？里面有哪些现成指标？」 |
| 人工记录 / 工单 | 线下流程、客诉、审批耗时 | 「这类事情目前有人工登记吗？翻记录能统计到多久的？」 |
| 负责人估算（最低置信） | 以上都不可得时 | 「能否请业务负责人给一个量级估计（个位 / 十 / 百 / 千）？」 |

约束：取数路径只引导获取**已存在**的数据；负责人估算必须标注 `ASSUMPTION` 并记录估算人，不得写成 FACT。PM 明确回复「取不到」后，才落 UNKNOWN 并记录已尝试的路径。

## SLA 候选值推导（目标不可量化时必做）

当目标是「提升效率 / 缩短时间 / 提高质量」这类不可直接度量的表述时，不得止步于定性描述，按以下框架推导候选指标：

1. **锚定现状**：先问当前值是多少（用上面的基线数据引导）。没有现状值，任何"缩短 X%"都无从验证。
2. **拆时间构成**：把总耗时拆成可分别观测的分段（等待 / 处理 / 传递 / 重试），候选 SLA 通常落在占比最大的分段上。
3. **列候选指标**：每段给出「指标名 + 统计口径（均值 / P90 / 最大值）+ 数据来源」。至少 2 个候选，供 PM 选择。
4. **区分承诺与观测**：对外承诺类（如响应 SLA）需要明确例外情形与豁免口径；内部观测类只需明确统计窗口。
5. **标注状态**：候选值未经 PM 确认前一律 `ASSUMPTION`；确认口径后才升 `DECISION`。

推导产物写入「目标与成功判断」章节，候选指标以表格呈现，未选定项保留并注明未采纳原因，供后续复盘。
